行動建議

  • 🔴 立即修補 Citrix NetScaler ADC/Gateway CVE-2026-88771 及 CVE-2026-88772（CVSS 9.5，零日漏洞，CISA KEV 9/27，已遭利用逾三週）：（1）確認所有 NetScaler ADC 及 Gateway 部署版本，立即升級至 14.1-38.53、13.1-57.18 或 13.0-98.99 以上修補版本；（2）修補後立即掃描所有 NetScaler 設備的程序列表，排查 WHIPSHOT 及 SLAPSHOT 惡意程式（查找異常的 root 程序或非標準二進位檔案）；（3）稽核 9 月 1 日以來的管理介面存取記錄，確認無未授權存取或設定變更；（4）檢查所有 NetScaler 設備的 cron job 及持久化機制（/etc/cron.d/、/var/spool/cron/ 及 systemd 服務）；（5）若確認設備已遭入侵，應立即隔離設備並通報資安應變團隊，進行完整鑑識調查後重新部署乾淨設備。
  • 🔴 立即升級 Gitea 至 1.27.1 並排查 Red Heron（CVE-2026-60004，CVSS 9.8，台灣 477 個目標遭掃描，SIXZUT rootkit）：（1）確認所有內部部署或雲端代管的 Gitea 實例版本，立即升級至 1.27.1 修補版本；（2）若無法立即升級，作為緊急緩解措施應限制 Gitea 的對外存取，僅允許受信任 IP 範圍；（3）掃描所有 Gitea 伺服器是否存在 SIXZUT rootkit（異常核心模組）及 JITTERLY 植入程式（非標準系統程序）；（4）確認 Gitea 儲存庫的存取記錄，搜尋 9 月 1 日以來的可疑複製（git clone/fetch）行為及非授權使用者存取；（5）稽核 Gitea 伺服器上的 SSH 授權金鑰，排除未知的 SSH 金鑰植入；（6）若發現入侵跡象，立即稽核受害 Gitea 儲存庫中的原始碼並評估可能的機密洩漏範圍（API 金鑰、資料庫憑證等）。
  • 🔴 立即升級 Zyxel GS1900 系列交換器韌體（CVE-2026-7273，CISA KEV，台灣全球第三受害國，FCEB 截止 9/24）：（1）盤點所有 Zyxel GS1900 系列交換器的部署清單及韌體版本，識別執行 2.90(XXXX.1)C0 或更早版本的受影響設備；（2）立即升級至 Zyxel 官方發布的修補韌體版本；（3）在升級韌體後，強制重置所有設備管理憑證（Web 管理帳號、SNMP 社群字串、CLI 帳號）；（4）將升級後的設備現行設定與備份設定檔進行比對，確認無未授權的 VLAN 設定、路由規則或管理帳號變更；（5）稽核過去 60 天的設備 Syslog，搜尋自 8 月 17 日前後的未授權 HTTP 請求及設定下載；（6）若確認設備設定已遭竊取，應評估受影響設備連接的內網拓撲，確認是否有針對性的橫向移動或後續攻擊。
  • 🔴 確認 Adobe Commerce/Magento 已完整修補 CVE-2026-75650 八步驟（CVSS 10.0，StyleSmuggler，每日逾 550 個利用嘗試）：（1）確認已套用 Adobe 熱修復 VULN-39341（9 月 7 日發布）；（2）依照 Adobe 官方修補指南執行完整八步驟修補，包括受感染範本清除及快取重置——僅套用熱修復不足以清除已植入的後門；（3）掃描所有 PHP 檔案是否包含可疑的 eval()、base64_decode() 或混淆程式碼（PHP 網頁殼特徵）；（4）搜尋系統中是否有非預期的 Rust 撰寫二進位程序（Linux 後門特徵）；（5）稽核 9 月 4 日以來的管理後台登入記錄及範本存取記錄，確認無未授權操作；（6）若為電商業者，應立即啟用信用卡交易監控，排查是否存在 Magecart 側錄腳本注入。
  • 🔴 立即套用 9 月 Patch Tuesday 更新並優先處理兩個積極利用的 Windows 本機提權零日：（1）確保 9 月 8 日 Patch Tuesday 所有安全更新已套用至所有 Windows 端點及伺服器，涵蓋 CVE-2026-85880（Windows ALPC 提權）及 CVE-2026-81963（Windows Update Stack 提權）；（2）稽核 EDR 警報，搜尋 9 月以來的異常 ALPC 呼叫及 Windows Update Stack 相關程序的非標準行為；（3）部署 9 月 Patch Tuesday 同時包含的 Windows DHCP Server CVE-2026-69845（CVSS 9.8）修補，若 DHCP 伺服器對外開放應立即優先修補；（4）利用 Windows 安全更新掃描工具確認所有端點的修補合規狀態，識別未修補的高風險設備。
  • 🟡 套用 CISA KEV 9/22 新增漏洞修補（Check Point、Arista VeloCloud、F5 BIG-IP）並稽核邊界防護設備：（1）確認所有 Check Point 量子安全閘道及 CloudGuard 版本，套用針對 CVE-2026-85102（不當憑證驗證）及 CVE-2026-93616（路徑遍歷）的修補；（2）稽核 Arista VeloCloud SD-WAN Orchestrator 版本，套用針對 CVE-2026-93952（不當輸入驗證）的修補；（3）確認 F5 BIG-IP APM 版本，套用針對 CVE-2026-94127（堆積式緩衝區溢位）的修補；（4）修補後稽核以上設備的管理存取記錄，確認無未授權的設定變更或可疑連線；（5）FCEB 機構截止日 10/13，台灣政府機關應同步參考此時程要求。
  • 🟡 強化 AI 開發環境安全與公開儲存庫憑證管理：（1）立即掃描所有公開及私有 GitHub/GitLab 儲存庫中的憑證洩漏，部署 GitHub Advanced Security Secret Scanning、Trufflehog 或 Gitleaks 等工具；（2）若發現任何憑證暴露，立即輪換並稽核相關服務的存取記錄；（3）開發及部署 AI 代理的組織，確認測試沙箱與正式環境的完整網路隔離——包括出站連線封鎖、無法存取外部網際網路及最小工具存取原則；（4）政府機關及關鍵基礎設施業者參考資安署揭露的老舊防火牆事件，建立設備 EOS（End of Support）追蹤清冊，確保所有邊界防護設備均在支援生命週期內，並有完整的交接及退場程序。
