行動建議

  • 🔴 立即修補 Cisco Secure Email Gateway CVE-2026-76461（CVSS 9.8，積極利用，CISA KEV 截止 9/17）：（1）確認所有 Cisco Secure Email Gateway 設備的 AsyncOS 版本，立即升級至 17.0 或以上修補版本；（2）無法立即修補者，評估暫時在上游郵件過濾層增加異常格式郵件攔截規則作為緩解，並確保管理介面不暴露於公共網路；（3）稽核 9/9（Microsoft Patch Tuesday 發布日）至今閘道上的異常 root 層級程序、可疑排程任務及非預期的出站連線；（4）Cisco PSIRT 確認主要影響對象為直接接收外部郵件的閘道，確認郵件路由設定中哪些設備直接暴露。
  • 🔴 立即修補 Cisco ISE CVE-2026-76460（CVSS 10.0，積極利用，CISA KEV 截止 9/19）及同套設備中的其他 CVSS 10.0 漏洞：（1）確認所有 ISE 及 ISE-PIC 部署版本，立即套用 Cisco 發布的修補版本；（2）修補前作為緩解措施，限制 REST API 的存取來源至受信任 IP 範圍，並停用未使用的 API 端點；（3）修補後立即稽核 ISE 管理員帳號清單（搜尋不明帳號）、存取政策異動記錄（過去 30 天）及任何非預期的策略變更；（4）評估 ISE 在企業零信任架構中的核心位置，確認是否有 ISE 管理員帳號具有過度廣泛的存取範圍。
  • 🔴 FortiBleed 後續應變——確認是否在 96 家受害企業名單內並立即輪換憑證：（1）聯繫 TWCERT/CC（service@twcert.org.tw）確認貴單位是否在受害名單中，資安署已掌握完整名單；（2）無論是否在名單中，凡部署 Fortinet FortiGate 防火牆或 SSL VPN 設備的組織應立即稽核所有 VPN 管理員及使用者帳號，並強制輪換所有本地帳號密碼；（3）確認 FortiGate 設備是否已套用 7 月 FortiBleed 相關的憑證重設修補及 Fortinet 建議的後續安全措施；（4）啟用多因素驗證（MFA）於所有 VPN 及遠端存取入口，作為憑證竊取後的最後防線；（5）稽核過去 60 天的 VPN 登入記錄，搜尋來自異常地理位置或在非工作時間的存取模式。
  • 🔴 立即套用 Microsoft 9 月 Patch Tuesday 並優先處理兩個積極利用零日及 CVSS 9.8 RCE 漏洞：（1）優先修補 CVE-2026-81963（Windows Update Stack EoP，積極利用）及 CVE-2026-85880（Windows ALPC EoP，積極利用）——兩者均為本地特權提升零日，常用於攻擊鏈的第二階段；（2）同等優先處理 CVSS 9.8 的 Windows DNS Server 及 DHCP Server 遠端程式碼執行漏洞，面向網路的 DNS/DHCP 服務若被攻陷影響全域；（3）面對 973 個 CVE，建議使用 Microsoft Exploitability Index 及 CVSS 分數雙重篩選，標記「Exploitation More Likely」的漏洞先行處理；（4）確認本月更新覆蓋所有受管 Windows 系統，包含伺服器、工作站及 Azure 混合環境。
  • 🔴 修補 SonicWall SMA1000（CVE-2026-83548/83549，CVSS 10.0）及 Citrix NetScaler（CVE-2026-19490，CVSS 9.3）——兩者均已確認積極利用：（1）SonicWall SMA1000：立即升級至 12.4.3-03526 或 12.5.0-02952，修補後假設設備已被入侵進行鑑識確認——搜尋非預期的新管理員帳號及近期設定變更；（2）Citrix NetScaler：確認設備是否設定為 AAA 虛擬伺服器或 Gateway 模式，套用 8/19 修補（PoC 已於 9/2 公開）；修補後稽核過去 30 天的 VPN 登入記錄及異常會話；（3）若任一設備已確認受損，立即隔離並啟動事件應變，評估攻擊者可能已取得的網路存取範圍。
  • 🟡 修補 MikroTik RouterOS 並停用未使用服務（CVE-2026-67277/CVE-2026-86060，CISA KEV 9/10，自 9/2 積極利用）：（1）盤點所有 MikroTik RouterOS 設備，立即升級至 6.49.21、7.23.4 或 7.24.2；（2）修補前暫時停用頻寬測試服務（btest）作為緩解措施（/tool bandwidth-server set enabled=no）；（3）確認路由器管理介面（Winbox、WebFig）未暴露於公共網路，限制存取來源至受信任 IP；（4）MikroTik 設備常見於台灣 ISP 及分支機構，建議進行完整網路設備盤點，確認版本覆蓋率。
  • 🟡 評估虛擬主機及雲端服務供應鏈安全——應對 UAT-7237 型 APT 的新威脅模型：（1）若貴單位使用第三方虛擬主機或雲端託管服務，評估供應商的資安防護狀況，要求提供近期滲透測試報告及事件記錄；（2）稽核企業與虛擬主機供應商之間的憑證共享範圍，確認是否有跨越信任邊界的服務帳號；（3）在企業環境中部署的 SoftEther VPN 及 RDP，確認均已套用存取控制及記錄稽核，因 UAT-7237 以此為持久化工具；（4）對關鍵應用程式的虛擬主機環境增加網路流量異常監控，偵測如 UAT-7237 般的低速隱密偵察行為。
